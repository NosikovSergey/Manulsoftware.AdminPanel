# Панель администратора — бизнес-требования

## Пользователи

Администратор должен иметь возможность найти любого пользователя по имени, username или Telegram ID.

По каждому пользователю доступна следующая информация:
- Профиль: имя, username, дата регистрации, последняя активность
- Текущий баланс (может быть отрицательным — фиксируется как долг)
- Флаг «Пробный период использован»
- История заказов
- Привязанные ключи доступа
- История транзакций

Доступные действия над пользователем:
- Заблокировать / разблокировать — заблокированный пользователь не может взаимодействовать с ботом; его активные ключи при этом продолжают работать. Требует добавления проверки поля `Status` в middleware бота.
- Выдать или забрать права администратора в боте — даёт доступ к командам администратора в Telegram-боте. Не влияет на доступ к веб-панели: доступ к панели управляется отдельными учётными записями.
- Сбросить пробный период — пользователь снова получает доступ к кнопке «Попробовать бесплатно»

---

## Ключи доступа

По каждому ключу отображаются данные из двух источников одновременно — из нашей базы и напрямую из Marzban. Расхождение между ними видно сразу.

Информация о ключе:
- Статус по нашей базе (активен / отключён / истёк)
- Статус в Marzban (активен / на удержании)
- Сервер, на котором выдан
- Дата истечения
- Использованный и общий трафик (из Marzban)

Доступные действия:
- Включить / отключить ключ — трафик прекращается или возобновляется немедленно
- Продлить бесплатно — дата истечения сдвигается вперёд, деньги с баланса не списываются, новый заказ не создаётся
- Восстановить ключ — принудительно синхронизирует состояние с Marzban: создаёт пользователя если пропал, исправляет статус и дату если расходятся

## Заказы

По каждому заказу видна следующая информация:
- Статус (создан / оплачен / выдан / истёк / отменён / возвращён)
- Тариф
- Привязанный ключ доступа
- Временны́е метки (когда создан, когда истекает)

Доступные действия:
- **Отменить и вернуть деньги** — единое действие для зависших заказов (ключ не был выдан). Система сама определяет состояние: если деньги на холде — снимает резервирование; если уже списаны — возвращает на баланс. Ключ при этом отключается если был создан.
- **Вернуть деньги** — для активных заказов по явной просьбе пользователя. Возврат производится в любом случае без проверки срока использования. Ключ отключается немедленно. Деньги зачисляются на внутренний баланс в боте; реальный возврат через платёжную систему делается отдельно вне панели через менеджера.

---

## Транзакции

Доступен просмотр полной истории транзакций: пополнения и возвраты.

Доступные действия:
- **Откатить транзакцию пополнения** — применяется при мошенничестве (чарджбэк через банк). Сумма вычитается из баланса пользователя; баланс может уйти в минус и фиксируется как долг. Активные ключи не затрагиваются.

---

## Тарифы

Администратор видит все существующие тарифы с их параметрами.
Пробный тариф в панели не отображается и не редактируется — он встроен в логику системы.

Доступные действия над тарифом:
- Изменить цену
- Включить / выключить (выключенный тариф не виден пользователям)
- Поставить или снять отметку «лучший выбор»

Пользователи, у которых уже открыто меню выбора тарифа в боте, увидят новую цену при следующем запросе — это допустимо.

Создание тарифов с произвольной длительностью — вне текущего scope.

---

## Разграничение блокировок

**Блокировка пользователя** — запрещает взаимодействие с ботом. Существующие ключи продолжают работать до истечения срока.

**Блокировка ключа** — отключает конкретный ключ; трафик прекращается немедленно. Пользователь при этом может продолжать пользоваться ботом и другими ключами.

---

## Аутентификация

Вход по логину и паролю. Сессия классическая, cookie-based.

Учётные записи хранятся в отдельной таблице БД — не связаны с Telegram-пользователями. Аккаунты создаются вручную (через миграцию или напрямую в БД), UI для управления учётными записями отсутствует.

В панели доступна вкладка «Сменить пароль» для текущего авторизованного пользователя.

---

## Что остаётся за рамками текущего scope

- Dashboard со статистикой (новые пользователи, выручка, конверсия)
- Аналитика кампаний
- Управление VPN-серверами
- Реальный возврат через Platega (делается вручную)
- Создание новых тарифов
- Перенос ключа на другой сервер
- Прощение долга (обнуление отрицательного баланса)
