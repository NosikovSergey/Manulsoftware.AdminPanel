# Сценарии работы администратора

## Сценарий 1: «Оплатил, но ключ не пришёл»

Пользователь написал в поддержку: деньги списались, но VPN-ключ не был выдан.

**Что делает администратор:**
1. Находит пользователя по Telegram ID или username
2. Смотрит историю транзакций — есть ли зависшая (статус Pending означает деньги на холде)
3. Смотрит статус заказа — на каком этапе застрял

**Возможные ситуации:**

| Что случилось | Деньги | Заказ |
|---|---|---|
| Marzban лёг, система сама откатила | Автоматически возвращены | Отменён |
| Marzban лёг, Hangfire ещё пытается | На холде | Created |
| Hangfire упал, задача зависла | На холде или списаны | Created / Paid |

**Действие администратора:**
- Нажать «Отменить и вернуть деньги» — система сама разберётся в каком состоянии заказ и сделает корректный откат (снимет холд или вернёт уже списанные деньги на баланс)
- Сообщить пользователю что деньги возвращены и можно попробовать снова

**Решения принятые при разработке:**
- Кнопки «Перезапустить обработку» не будет — слишком высок риск задублировать задачу в Hangfire. В крайнем случае инженер может сделать это вручную через дашборд Hangfire.
- Возврат только на внутренний баланс. Реальный возврат через Platega — вручную через менеджера.

## Сценарий 2: «VPN перестал работать»

Пользователь написал в поддержку: раньше VPN работал, сейчас не подключается.

**Что делает администратор:**
1. Находит пользователя, открывает карточку его ключа
2. Видит одновременно данные из нашей базы и живые данные из Marzban — расхождение заметно сразу

**Возможные причины и действия:**

| Причина | Что видит администратор | Действие |
|---|---|---|
| Трафик исчерпан (300 ГБ) | Marzban показывает 300/300 ГБ | Объяснить пользователю; при необходимости продлить бесплатно — трафик сбросится |
| Ключ просрочен | Дата истечения в прошлом | Сообщить пользователю что подписка закончилась |
| Ключ пропал из Marzban | Расхождение: у нас есть, в Marzban нет | Нажать «Восстановить ключ» |
| Расхождение статуса | У нас активен, в Marzban OnHold | Нажать «Восстановить ключ» |

**«Восстановить ключ»** — берёт актуальные данные из нашей базы и принудительно применяет их в Marzban: создаёт пользователя если пропал, исправляет статус и дату если расходятся.

## Сценарий 3: «Хочу вернуть деньги»

Пользователь явно просит возврат — недоволен сервисом, передумал, купил случайно. Подписка может быть активной.

**Политика:** возврат производится в любом случае, без проверки сколько пользователь уже использовал. Это дешевле репутационных издержек.

**Что делает администратор:**
1. Находит пользователя, открывает его активный заказ
2. Нажимает «Вернуть деньги»
3. Система за один шаг: отключает ключ в Marzban + возвращает сумму заказа на внутренний баланс пользователя + помечает заказ как Refunded
4. Если пользователь хочет реальный возврат на карту — это отдельно, вручную через менеджера в Platega

## Сценарий 4: Мошенничество — чарджбэк через банк

Пользователь пополнил баланс через Platega, сделал чарджбэк через банк (вернул деньги себе), но продолжает пользоваться VPN.

**Два независимых действия:**

**1. Откат транзакции пополнения**
- Администратор находит транзакцию пополнения в истории пользователя
- Нажимает «Откатить транзакцию»
- Сумма вычитается из баланса пользователя — баланс может уйти в минус, это фиксируется как долг
- Пользователь с отрицательным балансом не сможет купить новые подписки
- Активные ключи при этом не затрагиваются

**2. Блокировка пользователя** (отдельное действие)
- Запрещает взаимодействие с ботом
- Активные оплаченные ключи продолжают работать до истечения срока — пусть пользуется тем за что реально заплатил

## Сценарий 5: Изменение тарифов

Рутинная задача без внешнего триггера — администратор сам решает поднять цену, выключить тариф или сменить «лучший выбор».

**Что делает администратор:**
1. Открывает список тарифов
2. Выбирает нужный и меняет цену / включает-выключает / переставляет отметку «лучший выбор»
3. Изменения применяются немедленно

**Поведение при изменении цены:**
- Пользователи, у которых уже открыто меню выбора тарифа в боте, увидят старую цену до следующего запроса — это допустимо
- Уже оформленные заказы и активные подписки не затрагиваются

## Сценарий 6: Бесплатное продление как компенсация

Пользователь столкнулся с проблемой — сервис не работал, поддержка долго отвечала, произошёл какой-то сбой. Администратор хочет продлить подписку в знак доброй воли.

**Что делает администратор:**
1. Открывает карточку ключа пользователя
2. Выбирает длительность продления (1 месяц, 3 месяца и т.д.)
3. Нажимает «Продлить бесплатно»
4. Дата истечения ключа сдвигается вперёд, деньги с баланса пользователя не списываются, новый заказ не создаётся

## Сценарий 7: Управление правами администратора

Нужно выдать или забрать права администратора у другого пользователя — например, добавить нового сотрудника поддержки.

**Что делает администратор:**
1. Находит пользователя по Telegram ID или username
2. На карточке пользователя выдаёт или отзывает права администратора
3. Изменение применяется немедленно — пользователь получает или теряет права администратора в Telegram-боте (доступ к командам /give_admin, /balance и т.д.)

**Важно:** это не то же самое что доступ к веб-панели администратора. Доступ к веб-панели управляется отдельно через учётные записи в БД панели — создаются вручную.

## Сценарий 8: Сброс пробного периода

Пользователь уже использовал бесплатный пробный день, но администратор хочет дать ему второй шанс — например, в качестве компенсации или по индивидуальному решению.

**Что делает администратор:**
1. Открывает карточку пользователя
2. Видит что флаг «Пробный период использован» выставлен
3. Нажимает «Сбросить пробный период»
4. Пользователь снова видит в боте кнопку «Попробовать бесплатно»
