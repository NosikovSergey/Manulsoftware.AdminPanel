# Задачи фронтенда: Панель администратора

Отдельный репозиторий. SPA-приложение.  
Базовый URL API: настраивается через переменную окружения `VITE_API_URL` (или аналог).  
Все запросы к API отправляются с `credentials: "include"` — сессия передаётся через cookie.

При получении `401` от любого API-запроса — редирект на страницу входа.

## P1

---

### Задача 1.1 — Общий каркас приложения

- Левый сайдбар с пунктами навигации: «Пользователи», «Тарифы»
- Шапка: имя администратора (из `GET /api/auth/me`), кнопка «Выйти» (`POST /api/auth/logout` → редирект на логин)
- Хлебные крошки на каждой странице
- При загрузке приложения вызвать `GET /api/auth/me`:
  - `200` → показать приложение
  - `401` → показать страницу входа

---

### Задача 1.2 — Страница входа

Роут: `/login`

Центрированная форма:
- Поле «Логин»
- Поле «Пароль»
- Кнопка «Войти»
- Сообщение об ошибке под формой

**API:**

`POST /api/auth/login`
```
Request:  { "login": "...", "password": "..." }
Response 200 → сохранить имя из { "name": "..." }, перейти на /users
Response 401 → показать "Неверный логин или пароль"
```

### Задача 1.3 — Поиск пользователей

Роут: `/users`

- Строка поиска. Запрос отправляется при вводе (debounce ~300мс), минимум 2 символа
- Пока строка пустая — таблица не показывается
- Результаты в таблице: Имя, Username, Telegram ID, Баланс, Статус, Дата регистрации
- Статус — цветной бейдж: «Активен» (зелёный) / «Заблокирован» (красный)
- Баланс — красным если отрицательный
- Клик на строку → `/users/{userId}`

**API:**

`GET /api/users?query=иван&page=1&pageSize=20`
```
Response 200:
[
  {
    "id": 123456789,
    "firstName": "Иван",
    "lastName": "Петров",
    "username": "ivanpetrov",
    "balance": 250.00,
    "status": "active",
    "dateJoined": "2024-01-15T10:00:00Z"
  }
]
```

### Задача 1.4 — Карточка пользователя

Роут: `/users/{userId}`  
Хлебные крошки: `Пользователи > Иван Петров`

При загрузке: `GET /api/users/{userId}`

**Верхний блок (всегда виден):**

Левая часть:
- Имя и фамилия
- `@username`
- Telegram ID
- Дата регистрации, последняя активность

Правая часть:
- Бейдж статуса
- Баланс (красный + «долг» если отрицательный)
- Бейдж «Пробный период использован» если `isTrialUsed: true`

**Кнопки действий:**

Все кнопки показывают диалог подтверждения перед отправкой запроса. После успеха — перезагрузить данные пользователя.

| Кнопка | Условие показа | API |
|---|---|---|
| «Заблокировать» | `status == "active"` | `POST /api/users/{userId}/block` |
| «Разблокировать» | `status == "banned"` | `POST /api/users/{userId}/unblock` |
| «Выдать права администратора» | `isAdmin == false` | `POST /api/users/{userId}/grant-admin` |
| «Забрать права администратора» | `isAdmin == true` | `POST /api/users/{userId}/revoke-admin` |
| «Сбросить пробный период» | `isTrialUsed == true` | `POST /api/users/{userId}/reset-trial` |

**Вкладки:** `Ключи | Заказы | Транзакции`

---

#### Вкладка «Ключи»

`GET /api/users/{userId}/keys`

Таблица: Сервер, Статус, Дата истечения  
Статус — бейдж: «Активен» (зелёный) / «Отключён» (красный) / «Истёк» (серый)  
Клик на строку → `/keys/{keyId}`

```
Response 200:
[
  {
    "id": 42,
    "serverName": "Netherlands #1",
    "status": "active",
    "expiredDate": "2026-06-12T00:00:00Z"
  }
]
```

---

#### Вкладка «Заказы»

`GET /api/users/{userId}/orders?page=1&pageSize=20`

Таблица: Тариф, Статус, Создан, Истекает  
Статус — бейдж с цветом:
- «Создан» — серый
- «Оплачен» — синий
- «Выдан» — зелёный
- «Истёк» — серый
- «Отменён» — красный
- «Возвращён» — оранжевый

Клик на строку → `/orders/{orderId}`

```
Response 200:
[
  {
    "id": "uuid",
    "tariffDuration": "OneMonth",
    "status": "issued",
    "createdAt": "2026-05-12T10:00:00Z",
    "expiredAt": "2026-06-12T00:00:00Z"
  }
]
```

Отображение `tariffDuration`: `OneMonth` → «1 месяц», `ThreeMonths` → «3 месяца», `SixMonths` → «6 месяцев», `OneYear` → «1 год»

#### Вкладка «Транзакции»

`GET /api/users/{userId}/transactions?page=1&pageSize=20`

Таблица: Дата, Тип, Сумма, Источник, Статус  
Клик на строку → `/transactions/{transactionId}`

```
Response 200:
[
  {
    "id": "uuid",
    "date": "2026-05-12T10:00:00Z",
    "visualType": "deposit",
    "amount": 299.00,
    "status": "committed"
  }
]
```

Отображение `visualType`:
- `deposit` → «Пополнение»
- `withdrawal` → «Списание»
- `refund` → «Возврат»
- `rollback` → «Откат пополнения»

Отображение `status`: `pending` → «В обработке», `committed` → «Проведена», `canceled` → «Отменена», `refunded` → «Возвращена»

### Задача 1.5 — Карточка ключа

Роут: `/keys/{keyId}`  
Хлебные крошки: `Пользователи > Иван Петров > Ключ #42`  
Ссылка на пользователя берётся из `userId` в ответе API.

При загрузке: `GET /api/keys/{keyId}`

```
Response 200:
{
  "id": 42,
  "userId": 123456789,
  "serverName": "Netherlands #1",
  "status": "active",
  "issuedDate": "2026-05-12T00:00:00Z",
  "expiredDate": "2026-06-12T00:00:00Z",
  "linkedOrderId": "uuid",
  "marzban": {
    "status": "active",
    "usedTrafficGb": 45.2,
    "totalTrafficGb": 300.0,
    "expiredDate": "2026-06-12T00:00:00Z"
  }
}
```

**Две колонки данных:**

Левая — «Наши данные»: сервер, статус, дата выдачи, дата истечения  
Правая — «Marzban (live)»: статус Marzban, прогресс-бар трафика (usedTrafficGb / totalTrafficGb), дата истечения

Отображение `marzban.status`: `active` → «Active», `on_hold` → «OnHold», `expired` → «Expired», `limited` → «Limited (трафик исчерпан)»

Если значения `expiredDate` из обеих колонок расходятся — подсветить строку жёлтым с текстом «Расхождение с Marzban»  
Если `status` расходится с `marzban.status` — аналогично

**Кнопки действий:**

| Кнопка | Условие показа | API |
|---|---|---|
| «Отключить» | `status == "active"` | `POST /api/keys/{keyId}/disable` |
| «Включить» | `status == "disabled"` | `POST /api/keys/{keyId}/enable` |
| «Восстановить ключ» | Есть расхождение с Marzban | `POST /api/keys/{keyId}/restore` |
| «Продлить бесплатно» | Всегда | Открывает диалог выбора длительности |

Диалог «Продлить бесплатно»: выпадающий список (1 месяц / 3 месяца / 6 месяцев / 1 год) + кнопка «Подтвердить»

`POST /api/keys/{keyId}/extend`
```
Request:  { "duration": "OneMonth" }
Response 200: { "newExpiredDate": "2026-07-12T00:00:00Z" }
```
После успеха — обновить дату истечения на странице.

**Связанный заказ:** если `linkedOrderId` не null — показать ссылку на `/orders/{linkedOrderId}`

### Задача 1.6 — Карточка заказа

Роут: `/orders/{orderId}`  
Хлебные крошки: `Пользователи > Иван Петров > Заказ`

При загрузке: `GET /api/orders/{orderId}`

```
Response 200:
{
  "id": "uuid",
  "userId": 123456789,
  "tariffDuration": "OneMonth",
  "amount": 299.00,
  "status": "issued",
  "createdAt": "2026-05-12T10:00:00Z",
  "expiredAt": "2026-06-12T00:00:00Z",
  "keyId": 42
}
```

**Данные на странице:**
- Статус — бейдж (цвета те же что в таблице заказов)
- Тариф — отображение длительности (OneMonth → «1 месяц» и т.д.)
- Сумма оплаты
- Даты
- Ссылка на пользователя → `/users/{userId}`
- Ссылка на ключ → `/keys/{keyId}` (если `keyId` не null)

**Кнопки действий:**

| Кнопка | Условие показа | API |
|---|---|---|
| «Отменить и вернуть деньги» | `status == "created"` или `status == "paid"` | `POST /api/orders/{orderId}/cancel-and-refund` |
| «Вернуть деньги» | `status == "issued"` | `POST /api/orders/{orderId}/refund` |

Текст диалога подтверждения для «Вернуть деньги»: «Ключ будет отключён, [amount] ₽ будут возвращены на баланс пользователя».  
После успеха — перезагрузить данные заказа.

### Задача 1.7 — Смена пароля

Роут: `/change-password`  
Доступна из шапки: имя администратора → «Сменить пароль»

- Поле «Текущий пароль»
- Поле «Новый пароль»
- Поле «Повторите новый пароль»
- Валидация на клиенте перед отправкой:
  - Новый пароль и повтор должны совпадать
  - Минимум 8 символов
  - Минимум одна заглавная буква
  - Минимум одна цифра
- Кнопка «Сохранить»

`POST /api/auth/change-password`
```
Request:  { "currentPassword": "...", "newPassword": "..." }
Response 200 → показать «Пароль успешно изменён»
Response 400 → показать сообщение об ошибке из { "error": "..." }
```

### Задача 2.2 — Управление тарифами

Роут: `/tariffs`  
Хлебные крошки: `Тарифы`

При загрузке: `GET /api/tariffs`

```
Response 200:
[
  {
    "id": 1,
    "duration": "OneMonth",
    "price": 299.00,
    "isEnabled": true,
    "isBestChoice": false
  }
]
```

Таблица: Длительность, Цена, Лучший выбор, Статус

**Инлайн-редактирование:**

- **Статус** — toggle (вкл/выкл). При клике:  
  `PATCH /api/tariffs/{id}` с `{ "isEnabled": true/false }`

- **Лучший выбор** — чекбокс. При клике:  
  `PATCH /api/tariffs/{id}` с `{ "isBestChoice": true/false }`  
  При включении «лучший выбор» у одного тарифа — визуально снять у остальных (бэкенд не снимает автоматически, только показываем что один выбран)

- **Цена** — клик на поле делает его редактируемым (input). Рядом появляются кнопки «Сохранить» и «Отмена». При сохранении:  
  `PATCH /api/tariffs/{id}` с `{ "price": 349.00 }`

```
Response 200:
{
  "id": 1,
  "duration": "OneMonth",
  "price": 349.00,
  "isEnabled": true,
  "isBestChoice": false
}
```
После успеха — обновить строку в таблице данными из ответа.
